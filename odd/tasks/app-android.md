# Feature: app-android

## Objective

Ship the study app (Plan IA + Mapa completo with checklists) as an Android APK downloadable from the GitHub repository's Releases, rebuilt automatically from the repo content.

## Problem

The app exists only as a private claude.ai artifact (https://claude.ai/artifact/LgMnTf56YBsuNTrb4pdrFQ), generated by throwaway scratchpad scripts. The user wants an Android app installed from GitHub. An APK cannot use the artifact's claude.ai sync, so progress is stored on the device (user accepted this tradeoff).

## Scope and constraints

- New: `app/` (generator + HTML template, versioned), `android/` (minimal Java WebView project), `.github/workflows/android.yml`, a short README section on installing.
- The same template must keep working for the artifact (claude.ai db sync) and standalone (localStorage only).
- No Android SDK locally: the build runs on GitHub Actions; signing key lives in GitHub secrets, never in the repo.
- Branch `feat/app-android`; Conventional Commits; no AI attribution. Push and secrets only after explicit user confirmation.
- Route: delegated direct (writer trigger: several non-trivial new files).

## Sync extension (user request 2026-10-11)

The user wants progress synced between the APK and the desktop. Chosen design: a private GitHub gist (`progreso.json`) reached with a user-created token (gist permission only), last-writer-wins per checklist item; the desktop switches from the claude.ai artifact to the same standalone page served by GitHub Pages.
